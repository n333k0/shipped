# Production input: project.json

`normalize-brief.mjs` turns the /start/ brief (`brief.json`, schema in `docs/build-flow.md`) into `project.json`, the one brief every production agent reads. The /start/ form stays the source; this only normalizes it. Example: `examples/brief.example.json` (a fictional restaurant). Tests: `npm run test:production`.

| Field | From the brief | Status |
|---|---|---|
| `id`, `created_at` | `id`, `created_at` | required (generated by the form) |
| `customer` {name, email, company, current_site, socials} | `contact`, `project` | **email, company required** |
| `package` {id, name, price, days, depositPct, pages, sections} | `project.product` + `src/data/site.ts` | **required**; "not sure" → `inferred.package` from the sitemap size, and a blocker until the client confirms |
| `category` {id, note} | `project.industry` | **required**; selects `website-archetypes/<id>.md` |
| `objectives` {goal, describe, selling, audience} | `project` | **goal, describe required**; others optional |
| `pages[]` {name, path, blocks[]} | `sitemap.pages` | optional (the strategist proposes one when empty) |
| `scope` {pages, sections, included_pages, included_sections, over} | computed | `over: true` means add-ons to quote |
| `functionality[]`, `functional_detail` | `functional` | optional |
| `brand` {has, locked, palette_hex, font_names, logo_upgrade, files} | `brand` | optional |
| `direction` {references, closest, traits, sliders, motion, typeface, ideal, ideal_why, competitors, competitors_diff} | `visual` | optional, strongly wanted (ideal and competitors drive the direction) |
| `content` {copy_status, permission_to_rewrite, story, files} | `copy` | optional |
| `technical` | `technical` | optional |
| `timeline` {preferred_week, business_days} | `project.preferred_week`, package | optional |
| `checkout` | `start` | intent only (pay or call); never a payment confirmation |
| `special` {notes, product_note} | `dump.notes`, `project.product_note` | optional |
| `inferred` | `inferred` + package guess | inferred |
| `intake` {blockers, optional_missing, brief_missing, ready_to_plan} | computed | blockers stop planning |

## Incomplete briefs

Required gaps become `intake.blockers`: the orchestrator stops and asks the owner, who asks the client. Optional gaps are listed so the strategist can work around them or the copywriter can mark them `[needed]`.

## Lead or order

`production.json` starts every project as `lead`. Planning is allowed (it feeds the proposal and the PDF). Build and delivery require `production.mjs authorize`, run only when the owner confirms payment or approval. When a payment provider is connected, its confirmation is what the owner checks before authorizing; automating that is a later decision (`decisions.md`, Open).
